# STEP 11. CMSをはじめて触る人のための手順

STUDIOのCMSを使ったことがない前提で書いている。
[STEP 10](./10-studio-implementation-guide.md) の Phase 2 を、この手順に置き換えてよい。

---

## 11-0. 作業を始める前に

### PCで開くこと

STUDIOのエディタは**PCのブラウザ専用**。スマートフォンからは
プロジェクト一覧は見られるが、編集はできない。Chrome または Safari の最新版で開く。

### 所要時間の目安

| 作業 | 時間 |
|---|---|
| CMSの使用状況を確認 | 5分 |
| モデルを4つ作る | 10分 |
| プロパティを48個作る | **2〜3時間** |
| カテゴリ6件を入れる | 20分 |
| 作品を1本入れてみる | 30分 |

プロパティ作成は単純作業だが数が多い。**1日で終わらせようとせず、2日に分けてよい。**
途中で中断しても壊れない。

---

## 11-1. そもそもCMSとは何か

SISIDENの文脈で言うと、CMSは**「決まった項目の並んだ入力フォームを自分で作る仕組み」**である。

```
ふつうのWebサイト        CMSを使ったWebサイト

ページを1枚ずつ作る       入力フォームを1つ作る
  ↓                        ↓
作品が10本なら            作品が10本でも1,000本でも
ページを10枚作る           入力するだけでページが増える
```

用語は3つだけ覚えればよい。

| 用語 | 意味 | SISIDENでの例 |
|---|---|---|
| **モデル** | 入力フォームの種類 | 「ドキュメンタリー」「記事」「人物」 |
| **プロパティ** | フォームの入力欄 | 「作品タイトル」「YouTube動画ID」「取材日」 |
| **アイテム** | 実際に入力した1件 | TONKAN、八丈島の作品、小倉さんの記事 |

つまりこれからやるのは、**「ドキュメンタリーを登録するための入力フォームを作る」**作業。

---

## 11-2. 絶対に守る3つのルール

### ルール1. ページのパス（URL）は後から変えられない

STUDIOはパスを変更しても**旧URLからの転送が自動で作られない**。
変更した瞬間に、外部からのリンクも検索結果も切れる。

→ [STEP 4](./04-url-design.md) の表のとおりに設定し、以後変更しない。

### ルール2. プロパティは後から足せる

こちらは安全。だから**初日は必須項目だけ作ればよい**。
この手順書が48項目に絞っているのはそのため（全部だと150項目以上ある）。

### ルール3. 作る順番がある

「記事」から作ろうとすると詰まる。記事は「作品」や「人物」を参照するため、
**参照される側から先に作る**必要がある。

```
1. CATEGORIES（何も参照しない）
2. PEOPLE
3. DOCUMENTARIES（PEOPLEを参照する）
4. ARTICLES（上の3つを参照する）
```

## 11-3. Step 1: 確認済みの現状（2026-09-21）

CMS画面の**左下**に、いちばん重要な数字が出ている。

```
アクティブモデル数   5 / 10      ← 残り5枠
公開アイテム数      31 / 5,000   ← 余裕十分
```

既存モデルは9個並んでいるが、枠を消費しているのは5個。
タグ型・カテゴリー型（`タグ` `職種` `制作事例-地域カテゴリ` `制作事例カテゴリー`）は
枠を消費していないように見える。

**既存のモデルは絶対に削除・編集しない。** コーポレートサイトの表示が壊れる。

### モデルの種別は4つある

`[ + ]` を押すと種別を選ぶ。**どれを選ぶかで枠を消費するかが変わる。**

| 種別 | 何のための型か | 枠 | 既存の例 |
|---|---|---|---|
| **記事タイプ** | 読み物。タイトル/Slug/Cover/公開日時が最初から付いている | 消費する | 新着記事、制作事例 |
| **ユーザータイプ** | 人物 | 消費する | 投稿者 |
| **カテゴリタイプ** | 分類 | **しない** | 制作事例カテゴリー |
| **カスタムタイプ** | 自由に項目を作る | **しない** | タグ、職種 |

### 最初にやる30秒の検証

枠を消費しないという読みが正しいか、実際に確かめる。

```
1. [ + ] > カテゴリタイプ  で「テスト」という名前のモデルを1つ作る
2. 左下の「アクティブモデル数」を見る
3. テストモデルを削除する
```

| 結果 | 意味 |
|---|---|
| **5 / 10 のまま** | 読みどおり。下の表のとおりに進む |
| **6 / 10 に増えた** | 枠を消費する。`AREAS` と `ORGANIZATIONS` はPhase 3まで作らない |

**自分で作ったテストモデルだけを削除する。既存モデルには絶対に触らない。**

## 11-4. Step 2: モデルを作る（10分）

Phase 1で作るのは**3つだけ**（+ カテゴリ1つ）。
**この順番で作ること**（後のモデルが前のモデルを参照するため）。

| 順 | モデル名 | **選ぶ種別** | 日本語の意味 | 枠 |
|---|---|---|---|---|
| 1 | `CATEGORIES` | **カテゴリタイプ** | 記事の分類6種類 | 0 |
| 2 | `PEOPLE` | **ユーザータイプ** | 人物 | 1 |
| 3 | `DOCUMENTARIES` | **記事タイプ** | ドキュメンタリー作品 | 1 |
| 4 | `ARTICLES` | **記事タイプ** | 記事 | 1 |

これで 5枠中3枠を使う。残り2枠。

`ISSUES`（社会課題）は Phase 2、`AREAS`（地域）と `ORGANIZATIONS`（企業・団体）は
Phase 3 で作る。**今は作らない。**

### 記事タイプを選ぶと最初から付いてくる項目

`DOCUMENTARIES` と `ARTICLES` を記事タイプで作ると、
タイトル・Slug・Cover・テキスト・公開日時などが最初から用意されている。

**チェックシートの項目と名前が違っていても、意味が同じなら使い回す。**

| チェックシートの項目 | 記事タイプの既定項目 |
|---|---|
| `title` | タイトル |
| `slug` | Slug |
| `key_visual` / `hero_image` | Cover |
| `published_at` | 公開日時 |

同じ意味の項目を二重に作らないこと。足りない項目だけ追加していく。

この時点では空の箱を作っただけ。中身は次で入れる。

> **Slugについて（重要）**
> 既存の記事はSlugが `3JcLQK8w` のようなランダム文字列のまま公開されている。
> SISIDEN MEDIAでは**アイテムを作るたびにSlugを手入力する**
> （[STEP 4-4の命名規則](./04-url-design.md)）。
> 一度公開したSlugは変更できない（変更すると404になる）ので、入力時に確定させる。

## 11-5. Step 3: プロパティを作る（2〜3時間）

### チェックシートを用意する

```bash
python scripts/media_export.py --format setup-minimal
```

`data/media_export/studio_cms_setup_minimal.csv` が出る。
**これを印刷するか、別のウィンドウで開いて、1行ずつ消し込みながら作業する。**

シートの読み方:

```
モデル,      プロパティ名,  表示ラベル,  STUDIOで選ぶタイプ,  参照先モデル,  選択形式,        必須
DOCUMENTARIES, people,      登場人物,    参照,              PEOPLE,       マルチセレクト,  ●
```

これは STUDIO の画面で以下のように入力するという意味。

```
[プロパティを追加]
  プロパティ名   : people
  表示ラベル    : 登場人物
  タイプ       : 参照
  参照先モデル   : PEOPLE
  選択形式     : マルチセレクト（複数選択できるほう）
  必須         : ON
```

### タイプの選び方

| シートの表記 | STUDIOで選ぶもの | どんなときに使うか |
|---|---|---|
| テキスト | テキスト（1行） | タイトル、名前、肩書き |
| テキスト（複数行） | テキスト（複数行） | リード文など、改行はするが装飾しない文章 |
| リッチテキスト | リッチテキスト | 本文。見出し・引用・画像を入れられる |
| 画像 | 画像 | 写真 |
| 日付 | 日付 | 公開日、取材日 |
| セレクト | セレクト | 決まった選択肢から1つ選ぶ |
| スラッグ | スラッグ | URLの末尾になる文字列 |
| 参照 | 参照 | 他のモデルのアイテムと結びつける |

### 「セレクト」の選択肢を入れる

シートの「選択肢」列に `公開 / 下書き / 非公開` とあるものは、
STUDIOの選択肢入力欄に**1行ずつ**入れる。

```
公開
下書き
非公開
```

`/` は区切り記号なので入力しない。

### 「参照」でつまずいたら

参照は「このアイテムと、別のモデルのアイテムを結びつける」機能。

```
ARTICLES（記事）の documentary プロパティ
  → DOCUMENTARIES（作品）を シングルセレクト で参照

意味: 「この記事は、どの作品の記事か」を1つ選ぶ
```

- **シングルセレクト** = 1つだけ選べる（記事の所属作品、執筆者）
- **マルチセレクト** = 複数選べる（登場人物、社会課題、タグ）

参照先のモデルが選択肢に出てこない場合は、そのモデルをまだ作っていない。
Step 2 に戻る。

### 作業のコツ

- 1モデル終わるごとに休憩する
- 入力ミスに気づいたら、その場で直す（後で直すと忘れる）
- **プロパティ名（英字）は正確に。** 表示ラベル（日本語）は多少違っても後で直せる
- 疲れたら CATEGORIES → PEOPLE まででその日は終える

## 11-6. Step 4: カテゴリ6件を入力する（20分）

CATEGORIES モデルに、以下6件をアイテムとして登録する。

| slug | number | name_en | name_ja | order |
|---|---|---|---|---|
| `interview` | 01 | INTERVIEW | 証言 | 010 |
| `field-note` | 02 | FIELD NOTE | 取材ノート | 020 |
| `social-issue` | 03 | SOCIAL ISSUE | 社会の構造 | 030 |
| `local-context` | 04 | LOCAL CONTEXT | 地域の文脈 | 040 |
| `insight` | 05 | INSIGHT | 洞察 | 050 |
| `after-story` | 06 | AFTER STORY | その後 | 060 |

`description`（定義文）は `content/categories/*.yaml` からコピーする。

> `order` を `1` ではなく `010` にしているのは、並び順を文字列で管理しているため。
> 後から間に項目を足したくなったとき、`015` を入れれば済む。

## 11-7. Step 5: 作品を1本だけ入れてみる（30分）

いきなり全作品を入れない。**1本入れて、想定どおり動くか確かめる。**

TONKAN を例にすると、入力する内容は `content/documentaries/tonkan.yaml` にある。
`TODO:` の箇所を実データに置き換えながら入力する。

特に注意する2つ。

| プロパティ | 入力するもの | 間違いやすい点 |
|---|---|---|
| `youtube_id` | `dQw4w9WgXcQ` | **URLではなくIDだけ。** `https://youtube.com/watch?v=` は含めない |
| `duration_iso8601` | `PT11M24S` | 11分24秒という意味。構造化データ専用。表示には使わない |

`status` は **`下書き`** のままにしておく。ページのデザインができてから公開する。

## 11-8. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| 参照先のモデルが選べない | そのモデルをまだ作っていない。Step 2 の順番どおりに作る |
| 「モデルの上限に達しました」 | 既存モデルが枠を使っている。[STEP 5-8 縮退案](./05-studio-cms-model.md)へ |
| プロパティの順番を間違えた | 問題ない。並べ替えできるし、機能には影響しない |
| プロパティ名を間違えて作った | 早めに直す。ページで使い始めた後だと修正が面倒になる |
| スマホで編集できない | 仕様。PCで開く |
| アイテムを保存したのにサイトに出ない | 正常。ページ側でCMSと接続する作業（[STEP 10 Phase 4](./10-studio-implementation-guide.md)）がまだ |

## 11-9. ここまで終わったら

次は**ページを作ってCMSと接続する**作業（[STEP 10 Phase 3〜4](./10-studio-implementation-guide.md)）。

ただしその前に、**実機で確認すべきことが5つ**ある
（[付録A-6](./studio-capability-matrix.md)）。CMSができた直後が確認のタイミング。

1. 動的ページのパスを `/sisiden/documentary/:slug` と3階層で設定できるか
2. 作品ページで「この作品の記事一覧」をフィルターで出せるか
3. YouTube埋め込みにCMSの値を差し込めるか
4. 構造化データ欄でマルチ参照を展開できるか
5. 希望のフォント（Zen Old Mincho / Noto Sans JP）があるか

**この5つの結果を教えてもらえれば、それに合わせて手順書を直す。**
どれがNGでも代替案は用意してある。
