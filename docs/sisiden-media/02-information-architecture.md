# STEP 2. 情報アーキテクチャ

## 2-1. 設計原理

### 原理1. 最上位単位は DOCUMENTARY

一般的なWebメディアは `記事 > カテゴリ > タグ` の階層を持つ。SISIDENはこれを採らない。

```
× 一般的なメディア          ○ SISIDEN
  カテゴリ                    DOCUMENTARY（作品）
   └ 記事                      ├ 記事群（1作品に3〜10本）
      └ タグ                   ├ 人物
                               ├ 社会課題
                               └ 地域
```

理由は、SISIDENの一次情報が**作品単位の取材**で発生するから。
情報の発生単位と情報設計の単位を一致させると、運用が破綻しない。
「今月は何を書くか」ではなく「この作品から何本出せるか」で企画が立つ。

### 原理2. 5つのエンティティで世界を記述する

SISIDENが扱う現実は、次の5つで記述できる。

| エンティティ | 問い | 役割 |
|---|---|---|
| **DOCUMENTARY** | 何を記録したか | 作品。すべての一次情報の発生源 |
| **PEOPLE** | 誰の人生か | 人物。作品を横断する資産 |
| **ISSUE** | どんな社会課題か | 社会課題。AIO（AI検索）の主戦場 |
| **AREA** | どこの話か | 地域。地域メディア・自治体案件との接続点 |
| **ORGANIZATION** | どの組織が関わるか | 企業・団体。E-E-A-Tと取材実績の証明 |

**ARTICLE（記事）はこの5つを結ぶ「辺」であって「点」ではない。**
記事は必ず、どれかのエンティティに接続して生まれる。接続先のない記事は作らない。

### 原理3. すべてのページは「次の問い」で終わる

読み終わりを作らない。各ページの末尾には必ず、
**別のエンティティへの導線**を配置する（STEP 6のワイヤーフレームで定義）。

## 2-2. コンテンツタイプ定義

### 8つのモデル

| # | モデル | 日本語 | ページ有無 | 想定件数（3年後） | 説明 |
|---|---|---|---|---|---|
| 1 | DOCUMENTARIES | ドキュメンタリー | ○ 詳細あり | 50〜150 | 作品。本編映像・STORY・背景・クレジット |
| 2 | ARTICLES | ストーリー | ○ 詳細あり | 500〜1,000 | 記事。6カテゴリに分類 |
| 3 | PEOPLE | 人物 | ○ 詳細あり | 150〜400 | 登場人物・専門家・制作者 |
| 4 | ISSUES | 社会課題 | ○ 詳細あり | 20〜40 | 課題ハブページ。**質で勝負・量産しない** |
| 5 | AREAS | 地域 | ○ 詳細あり | 20〜50 | 地域ハブページ |
| 6 | ORGANIZATIONS | 企業・団体 | △ 一覧のみ推奨 | 30〜80 | 企業・自治体・業界団体 |
| 7 | CATEGORIES | 記事カテゴリ | ○ 詳細あり | 6（固定） | 記事の編集的分類 |
| 8 | TAGS | タグ | △ 一覧のみ | 30〜60 | 横断タグ。**noindex推奨** |

STUDIO Businessプランのモデル上限10に対し8。残枠2。
【要確認】コーポレートサイトの既存モデル数によっては縮退案（STEP 5-7）を採用。

### なぜ PEOPLE をカテゴリではなくモデルにするか

要件では記事カテゴリの「07 PEOPLE」として人物アーカイブが挙げられていた。
これは**カテゴリではなくモデルにすべき**である。

| | カテゴリにした場合 | モデルにした場合（推奨） |
|---|---|---|
| 1人が複数作品に出る | 記事を複製するか、記事内に併記するしかない | 1つの人物ページが複数作品にひも付く |
| 人物からの回遊 | 不可 | 人物 → 出演作品 → 別の記事へ回遊 |
| 構造化データ | Article止まり | **Person + それを参照するVideoObject/Article** が組める |
| AI検索 | 「小倉莉恩とは誰か」に答えられない | エンティティとして認識される |

人物を資産にするなら、人物は**点（エンティティ）**でなければならない。

## 2-3. 記事カテゴリ設計（6分類）

要件の7分類から `07 PEOPLE` をモデルへ移し、名称をSISIDENの世界観に合わせて調整した。

| # | 英語名 | 日本語表記 | 定義 | 1作品あたり目安 |
|---|---|---|---|---|
| 01 | **INTERVIEW** | 証言 | 主人公・登場人物へのロングインタビュー。一人称の語り | 1〜3本 |
| 02 | **FIELD NOTE** | 取材ノート | ディレクター・プロデューサーによる現場記録と制作の裏側 | 1〜2本 |
| 03 | **SOCIAL ISSUE** | 社会の構造 | 映像の背景にある社会課題・産業構造の解説 | 1〜2本 |
| 04 | **LOCAL CONTEXT** | 地域の文脈 | 地域の歴史・構造・課題。課題だけでなく前提を含む | 0〜1本 |
| 05 | **INSIGHT** | 洞察 | 専門家・有識者による解説。「洞察の架け橋」 | 0〜2本 |
| 06 | **AFTER STORY** | その後 | 公開後に主人公・地域・プロジェクトに起きた変化 | 0〜1本（半年後） |

### 名称変更の理由

- `DOCUMENTARY NOTE` → **`FIELD NOTE`**
  「DOCUMENTARY」はモデル名として既に最上位で使っている。同じ語を2つの意味で使うと
  情報設計が濁る。`FIELD NOTE` は「現場で書いたノート」を直接示し、一次情報性が伝わる。

- `LOCAL ISSUE` → **`LOCAL CONTEXT`**
  地域を「課題」としてだけ扱うと、取材先である地域に対する立場が一方的になる。
  歴史・産業・文化という前提（文脈）ごと扱う語にする。SISIDENの倫理的な立ち位置の表明でもある。

- `SOCIAL ISSUE` は英語名を維持し、日本語表記を**「社会の構造」**とする。
  「社会課題の解説」は他メディアと同質化する。SISIDENは課題を論じるのではなく
  **構造を見せる**メディアである。

### カテゴリ運用ルール

- 1記事 = 1カテゴリ（複数付与禁止）。複数該当するなら記事が分けられていない
- カテゴリは**増やさない**。7つ目が欲しくなったら、それはタグかISSUEで表現できる
- 各カテゴリページには編集部による定義文を置く（AI検索が分類を理解するため）

## 2-4. タグ（横断軸）設計

タグは「なんでも入れる箱」にすると3年で必ず破綻する。**3つの軸に分けて管理する。**

### 軸1: ISSUES（社会課題）— モデル化・ハブページあり

記事につける単なるラベルではなく、**それ自体が読み物**になるハブページを持つ。
AI検索対策の中核。**20〜40個に絞り、1つずつ本気で作る。**

```
地域創生 / 若者の居場所 / 地域コミュニティ / 担い手不足 / 職人の技術継承
災害復旧 / 資源循環（鉄リサイクル等） / 金融教育 / キャリア教育 / 2拠点居住
一次産業の継承 / 物流の2024年問題 / 建設業の未来 / 過疎と離島 / 環境と産業
```

判定基準: **「これは問いとして立つか？」**
「#建設」はタグ、「建設業の担い手不足はなぜ起きているのか」はISSUE。

### 軸2: AREAS / ORGANIZATIONS / PEOPLE — 固有名詞はモデル化

固有名詞をタグにしてはいけない。固有名詞は**エンティティ**である。

| 分類 | 例 | 格納先 |
|---|---|---|
| 地域 | 横浜 / 八丈島 / 飯塚 / 対馬 / 北海道 / 磐梯 | AREAS |
| 企業・団体 | 鹿島建設 / 金融庁 / TONKAN / 鉄リサイクル工業会 | ORGANIZATIONS |
| 人物 | 小倉莉恩 / 専門家 / プロデューサー | PEOPLE |

理由: 固有名詞をタグにすると、`Person` `Place` `Organization` の構造化データが組めず、
AI検索がエンティティとして認識しない。SISIDENの資産は固有名詞そのものである。

### 軸3: TAGS（横断タグ）— 軽量ラベル

上記に当てはまらない、テーマ・感情・産業の軽量ラベル。

```
#ものづくり #職人 #教育 #環境 #サステナビリティ #AI #物流 #建設 #金融
#若者 #居場所 #地方自治 #継承 #挑戦 #再生
```

運用ルール:
- タグページは作ってよいが **`noindex`** にする（薄いページの量産を防ぐ）
- 1記事につき最大5個
- 新規タグ追加は月1回の棚卸し時のみ（記事作成時に思いつきで増やさない）

### 3軸の使い分け早見表

```
その語で「1つの読み物」が書けるか？
├─ YES → ISSUES（ハブページを作る）
└─ NO  → 固有名詞か？
          ├─ YES → AREAS / ORGANIZATIONS / PEOPLE
          └─ NO  → TAGS（noindex）
```

## 2-5. リレーション設計

### 全リレーション一覧

| From | To | 多重度 | 方向 | 用途 |
|---|---|---|---|---|
| ARTICLE | DOCUMENTARY | n:1（必須） | 記事→作品 | 記事末尾「この物語を映像で見る」 |
| ARTICLE | CATEGORY | n:1（必須） | 記事→分類 | 記事の分類 |
| ARTICLE | PEOPLE | n:n | 記事→人物 | 登場人物・執筆者・監修者 |
| ARTICLE | ISSUE | n:n | 記事→課題 | 関連社会課題 |
| ARTICLE | AREA | n:n | 記事→地域 | 取材地 |
| ARTICLE | ORGANIZATION | n:n | 記事→組織 | 登場組織 |
| ARTICLE | TAG | n:n | 記事→タグ | 横断タグ |
| DOCUMENTARY | PEOPLE | n:n | 作品→人物 | 登場人物・制作クレジット |
| DOCUMENTARY | ISSUE | n:n | 作品→課題 | この作品から見える社会課題 |
| DOCUMENTARY | AREA | n:n | 作品→地域 | 舞台 |
| DOCUMENTARY | ORGANIZATION | n:n | 作品→組織 | 取材先・協力 |
| PEOPLE | AREA | n:n | 人物→地域 | 活動地域 |
| PEOPLE | ORGANIZATION | n:n | 人物→所属 | 所属・肩書き |
| ISSUE | AREA | n:n | 課題→地域 | 課題が現れている地域 |

### 重要: STUDIOでの「逆参照」の扱い

STUDIO CMSの参照プロパティは**片方向**である。
`ARTICLE → DOCUMENTARY` を設定しても、DOCUMENTARY詳細ページで
「この作品に紐づく記事一覧」を自動表示する専用機能はない。

実現手段は2つ。

| 方式 | 内容 | 判定 |
|---|---|---|
| **A. 動的リストのフィルター**（第一候補） | DOCUMENTARY詳細ページにARTICLESの動的リストを置き、フィルター条件に「参照プロパティ = 現在のページのアイテム」を設定 | 2026年4月のCMSアップデートで複合フィルターが強化済み。**【要確認】現在のページの値を条件に使えるか**を実機で検証 |
| **B. 双方向で参照を張る**（確実な代替） | DOCUMENTARY側にも `related_articles`（ARTICLESへのマルチ参照）を持たせ、記事公開時に両側を更新 | 確実に動く。運用コストは「記事1本につき2箇所更新」。**編集フローに組み込めば破綻しない** |

→ **設計上は B を前提に組む**（STEP 5のモデル定義に `related_articles` を含める）。
Aが実機で動けばBの手動更新を省略できるが、**Bのプロパティは残しておく**
（編集部が「この作品の代表記事3本」を意図的に並べ替えたい場面が必ず来るため、
自動フィルターだけでは足りない）。

この二重化は冗長ではなく、**「自動の網羅」と「編集の意図」を両立させる設計**である。

## 2-6. ナビゲーション設計

### SISIDEN専用グローバルナビ

```
SISIDEN                                                    [検索] [YouTube]
  DOCUMENTARIES   STORIES   PEOPLE   ISSUES   AREAS   ABOUT
```

- 左上ロゴは **SISIDEN**。シシクリエイションのロゴは置かない
- `STORIES` = 記事。`ARTICLES` ではなく `STORIES` とする
  （URLも `/stories/` に統一。ナビラベルとURLを一致させることは、
  ユーザーの位置把握にもAIのサイト構造理解にも効く）
- `AREAS` は作品数が少ない初期は非表示でもよい（10地域を超えたら出す）
- 検索は初期は省略可（STEP 7の回遊設計で代替）

### フッター

```
─────────────────────────────────────────────
SISIDEN
物語から、社会を知る。

DOCUMENTARIES     STORIES          ABOUT
作品一覧           証言              SISIDENについて
                  取材ノート         編集方針
ISSUES            社会の構造         取材ポリシー
社会課題から探す    地域の文脈         お問い合わせ
                  洞察
PEOPLE            その後
AREAS

YouTube / X / note
─────────────────────────────────────────────
Produced by SISI CREATION →  （株式会社シシクリエイション）
© SISI CREATION Inc.
─────────────────────────────────────────────
```

コーポレートへの接続は**フッター最下部の1行のみ**。
これにより「独立した編集メディア」という読者の認識を壊さずに、
運営主体の透明性（E-E-A-T）を確保する。

## 2-7. 回遊（Knowledge Graph）の設計

### 回遊パスの定義

```
       ┌──────────────── 検索・SNS・YouTube からの流入 ─────────────────┐
       ▼                            ▼                                ▼
 ┌──────────┐              ┌──────────────┐                  ┌─────────┐
 │  ISSUE   │◀────────────▶│  DOCUMENTARY │◀────────────────▶│ ARTICLE │
 │ 社会課題   │              │     作品      │                  │  記事    │
 └────┬─────┘              └──────┬───────┘                  └────┬────┘
      │                           │                               │
      │         ┌─────────────────┴───────────────┐               │
      ▼         ▼                                 ▼               ▼
 ┌─────────┐ ┌────────┐                     ┌──────────┐    ┌─────────┐
 │  AREA   │ │ PEOPLE │────────────────────▶│ 別の作品  │◀───│ 別の記事 │
 └─────────┘ └────────┘                     └──────────┘    └─────────┘
```

### 各ページの「出口」設計（必須配置）

| ページ | 必ず置く出口 |
|---|---|
| 記事 | ①この物語を映像で見る（作品へ） ②登場人物 ③関連社会課題 ④関連記事 |
| 作品 | ①関連記事一覧 ②登場人物 ③社会課題 ④地域 ⑤次に見るべき作品 |
| 人物 | ①出演作品 ②この人物が登場する記事 ③関連する社会課題 ④同じ地域の人物 |
| 社会課題 | ①関連作品 ②関連インタビュー ③関連地域 ④隣接する社会課題 |
| 地域 | ①その地域の作品 ②記事 ③人物 ④その地域に現れている課題 |

**最低3つの異なるエンティティ型への出口**を各ページに置く。
これが「1記事読んで離脱」を防ぎ、同時にAI検索に対して
「このサイトは相互に接続された知識体系である」というシグナルを送る。

### 回遊の質を測る指標

記事数ではなく、以下をKPIとする。

| 指標 | 定義 | 目標 |
|---|---|---|
| ノード数 | DOCUMENTARY + PEOPLE + ISSUE + AREA の合計 | - |
| エッジ数 | 設定済みリレーションの総数 | ノード数 × 4以上 |
| 孤立ノード率 | 接続が2以下のノードの割合 | 10%未満 |
| 1作品あたり記事数 | ARTICLES ÷ DOCUMENTARIES | 3以上 |
| セッションあたり回遊数 | GA4 | 2.0以上 |

本リポジトリの `scripts/media_validate.py` がノード数・エッジ数・孤立ノードを
自動集計する（[付録C](./integration-toolkit.md)）。
