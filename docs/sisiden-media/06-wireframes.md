- ニュースメディアのような「新着一覧の羅列」を作らない

- 記事末尾の「この物語を映像で見る」は**装飾ではなく最重要導線**。
  CTAボタンではなく、作品カードそのものを大きく置く
- 出口が4種類（作品・人物・課題・記事）= 回遊設計（[STEP 2-7](./02-information-architecture.md)）

AIが引用する際に必要な要素を過不足なく順に並べた形である。

## 6-7. レスポンシブ方針

| ブレークポイント | 幅 | 主な変化 |
|---|---|---|
| Desktop | 1280px〜 | 3カラム / 本文680px / HERO 100vh |
| Laptop | 1024〜1279px | 3カラム維持 / 余白圧縮 |
| Tablet | 768〜1023px | 2カラム / HERO 80vh |
| Mobile | 〜767px | 1カラム / HERO 70vh / 本文は左右24pxマージン |

**モバイルで特に守ること**

- 記事のリードは**モバイルでも省略しない**（AIとユーザーの両方が最初に読む部分）
- 作品詳細のYouTube埋め込みは画面幅いっぱい
- 人物の丸ポートレートは横スクロール（縦に積まない）
- 「この物語を映像で見る」は**画面下に固定表示**してもよい（記事が長いため）
