# 付録A. STUDIO「できる / 難しい / 代替」一覧

STEP 1〜10で判明した制約を1枚に集約したもの。実装中はこの表を参照する。

凡例: ◎ 問題なくできる ／ ○ できる ／ △ 条件付き・要検証 ／ × できない

---

## A-1. サイト構造・URL

| # | やりたいこと | 可否 | STUDIOでできること | 難しいこと | 代替方法 |
|---|---|---|---|---|---|
| 1 | `sisicreation.com/sisiden/` にメディアを作る | ◎ | 同一プロジェクトにページを追加すればよい | - | - |
| 2 | 別プロジェクトをサブディレクトリにマウント | △ | カスタムプロキシ（Business Plusアドオン）で**別サーバーのサイト**を表示可能 | 別のSTUDIOプロジェクトをマウントできるかは公式に明示されていない（`/_nuxt` の衝突リスク） | 同一プロジェクト内に構築する（推奨） |
| 3 | 3階層のURL `/sisiden/documentary/:slug` | △ | 動的ページのパスは `パス + :slug` で構成 | **多階層パスの可否は実機確認が必要** | 2階層 `/documentary/:slug` に切り替え（[STEP 4-5](./04-url-design.md)）。その場合も `/sisiden/` トップは作る |
| 4 | 公開後のURL変更 | × | - | パス変更時に301が自動生成されない。旧URLが404化する | **公開前にパスを確定させる**。設計書の表をそのまま設定 |
| 5 | 301リダイレクト設定 | △ | **【要確認】** | ワイルドカード対応は不明 | CDN/プロキシ層（Cloudflare等）で処理。またはパスを変更しない設計 |
| 6 | XMLサイトマップ | ◎ | 自動生成 | - | noindexページが除外されているか確認 |
| 7 | 独自ドメインへの移行 | ○ | 新プロジェクトで構築し直す | **CMSデータを持ち出せない**（#20参照） | 正本を外部に持つ（[付録C](./integration-toolkit.md)） |

| 17 | 承認フロー（編集長承認） | × | - | ワークフロー機能なし | `status` プロパティ + 運用ルール |
| 18 | 下書きプレビュー共有 | ○ | プレビューURL | - | - |
| 19 | CMSの一括インポート | △ | WordPress XML からの一括インポートに対応 | CSV直接インポートは非対応 | 本リポジトリの `scripts/media_export.py --format wxr` がWXRを生成 |

## A-6. 実機で最初に検証すべき6項目

実装着手時に、**この6つを最初の1時間で確認する**。
結果次第で設計が変わるため、後回しにしない。

| # | 検証項目 | 確認方法 | NGだった場合 |
|---|---|---|---|
| 1 | ~~プラン~~ / CMSモデル残枠 | **プランはBusinessで確認済**。残枠はCMSダッシュボードで確認 | 残枠が8未満なら縮退案（STEP 5-8） |
| 2 | 3階層の動的ページパス | テスト用動的ページを1つ作り `/sisiden/documentary/:slug` を設定 | 2階層構成へ（STEP 4-5） |
| 3 | 動的リストのフィルターに「現在のページのアイテム」を使えるか | 作品詳細にARTICLESリストを置き試す | 双方向参照へ（STEP 2-5） |
| 4 | YouTube埋め込みURLへのCMS値差し込み | 動的ページで試す | `youtube_url` プロパティ追加 |
| 5 | 構造化データ欄でのマルチ参照展開 | JSON-LD欄でマルチ参照プロパティを挿入 | `primary_issue` 方式へ（STEP 8-8） |
| 6 | 希望フォントの有無 | テキストスタイル作成時 | 代替書体（STEP 9-3） |
