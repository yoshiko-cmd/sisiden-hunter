# STEP 7. SEO / AIO 設計

## 7-1. 前提: SISIDENが戦う場所

SISIDENは**キーワード検索で勝つメディアではない**。

「若者 居場所」で検索順位を取りに行けば、既存の大手メディア・行政サイト・
量産SEOメディアと同じ土俵に乗ることになり、しかも資源で負ける。

SISIDENが勝てるのは次の3つ。

| 戦場 | 内容 | 勝てる理由 |
|---|---|---|
| **① 固有名詞検索** | 「小倉莉恩」「TONKAN」「八丈島 台風22号 復興」 | 一次情報を持つのがSISIDENだけ。競合がいない |
| **② AI検索の引用元** | ChatGPT / Gemini / Perplexity / AI Overviews が回答を組むときの出典 | 現場取材・当事者の声・取材日の明示は、AIが好む「検証可能な一次情報」 |
| **③ 指名・回遊** | 「SISIDEN」で来た人が3ページ以上読む | Knowledge Graph構造 |

**①→②→③の順で積む。**汎用キーワードは狙わない。

## 7-2. AIO（AI検索最適化）の実装

AI検索が引用するのは「読みやすい記事」ではなく、
**事実関係を確定できる記事**である。以下を構造として埋め込む。

### 原則1. 冒頭で問いに答える（Answer First）

各ページの最初のテキストブロックに、そのページの結論を置く。

| ページ | ブロック | ルール |
|---|---|---|
| 記事 | `lead` | **1文目で記事の問いに答える。** 2文目以降で文脈 |
| 社会課題 | `answer` | 200〜300字。「結論」ラベル付きで枠に入れる |
| 人物 | `lead` | 「{name}は、{所属}で{活動}している{属性}。」の形で始める |
| 作品 | `lead` | 「{title}は、{地域}の{人物}を追った{時間}のドキュメンタリー。」 |

**悪い例**
> 横浜のある街角に、小さな店がある。夕方になると、高校生たちが集まってくる ─。

**良い例**
> TONKANは、横浜市の若者たちが自ら立ち上げた「街の居場所」である。大学生の小倉莉恩を中心に、
> 2024年から運営が続いている。SISIDENは2026年8月、その現場を4日間取材した。

情緒的な書き出しは**本文の冒頭**で使う。リードは事実で書く。
**この使い分けが「AIが抽出できる文章」と「人間が読みたい文章」の両立点。**

### 原則2. 5W1Hを省略しない

| 要素 | 実装 |
|---|---|
| **Who** | 人物名をフルネーム + 肩書き + 所属で初出時に書く。代名詞で受けない |
| **What** | 固有名詞を略さない（「同社」「彼女」を避ける） |
| **When** | 取材日・出来事の年月を明記。「先日」「昨年」を使わない |
| **Where** | 都道府県 + 市区町村まで書く |
| **Why** | 「なぜそうなったか」を1段落で明示 |
| **How** | 数値・期間・回数を入れる |

### 原則3. 一次情報であることを機械可読にする

各記事に固定ブロックとして配置（[STEP 6-3](./06-wireframes.md)）。

```
この記事は、SISIDENが {interview_location} で {interview_date} に行った
取材をもとに制作しています。
取材対象 {interview_subjects}
取材・文 {author} ／ 撮影 {photographer} ／ 編集 {editor} ／ 監修 {supervisor}
公開 {published_at} ／ 更新 {updated_at}
```

これはE-E-A-Tの表示であると同時に、**AIに対する出典情報の提供**である。
構造化データ側でも同じ情報を `Article` の各プロパティに載せる（[STEP 8](./08-structured-data.md)）。

### 原則4. 見出しを問いの形にする

```
×  TONKANの取り組み
○  なぜ若者たちは、自分たちで居場所をつくったのか
```

AI検索は質問文に対して回答を返す。**見出しが質問文と一致していると引用されやすい。**

### 原則5. 出典を必ずリンクで示す

- 統計は省庁・自治体の**1次ソースに直接リンク**
- 「〜と言われている」を書かない。誰が言ったかを書く
- SISIDEN自身の取材が根拠の場合は「SISIDENの取材による」と明記する

### 原則6. エンティティを固定する

同じ人物・組織・地域は、サイト全体で**同じ表記**を使う。

| 対象 | 正表記 | 使ってはいけない表記 |
|---|---|---|
| メディア名 | SISIDEN | SisiDen / シシデン単独 |
| 運営会社 | 株式会社シシクリエイション | シシクリ / SISI |
| 人物 | 小倉 莉恩（おぐら りおん） | 小倉さん（初出時） |

表記揺れはAIのエンティティ解決を壊す。CMSの `PEOPLE` `ORGANIZATIONS` モデルを
参照して書く運用にすれば、自然に統一される（**これがモデル化のもう一つの利点**）。

## 7-3. SEOタイトル / メタディスクリプション設計

### 記事

```
SEOタイトル（32字以内）
  {title} ｜ {documentary} ｜ SISIDEN

  例: 「居場所って、つくれるんだと思った」｜TONKAN｜SISIDEN

メタディスクリプション（120字前後）
  {lead} の1〜2文目をそのまま使う（別途書き下ろさない）
```

### 作品

```
SEOタイトル
  {title}｜{subtitle}｜SISIDEN ドキュメンタリー

  例: TONKAN｜若者がつくった、街の居場所。｜SISIDEN ドキュメンタリー
```

### 社会課題

```
SEOタイトル
  {question}｜SISIDEN

  例: 若者の居場所とは何か？｜SISIDEN

  ★ 問いをそのままタイトルにする。検索クエリと一致しやすく、AI引用でも文脈が通る
```

### 人物

```
SEOタイトル
  {name}（{title}）｜SISIDEN

  例: 小倉莉恩（大学生 / TONKAN）｜SISIDEN
```

**共通ルール**

- サイト名は必ず末尾に `SISIDEN`
- 区切りは全角パイプ `｜` で統一
- キーワードの詰め込みをしない
- 記事タイトルとSEOタイトルを**別物にしない**（読者とクローラーで見せる情報を変えない）

## 7-4. OGP設計

| ページ | OGP画像 |
|---|---|
| 作品 | `key_visual`（16:9のまま流用可） |
| 記事 | `hero_image` |
| 人物 | `portrait` を1200×630にトリミングしたもの（別途用意） |
| 社会課題 | `hero_image` |
| トップ | 固定のブランドビジュアル |

- サイズ: 1200×630px
- **文字を焼き込まない**（SNSでタイトルは別途表示されるため二重になる）
- 例外: 人物ページのみ、名前を小さく入れてもよい

## 7-5. 内部リンク設計

内部リンクはSEOのためではなく**Knowledge Graphを成立させるため**に張る。

| ルール | 内容 |
|---|---|
| 記事本文 | 内部リンク最低3本。人物・課題・作品のいずれかへ |
| アンカーテキスト | 固有名詞そのもの（「こちら」「詳細はこちら」を使わない） |
| 相互リンク | 作品↔記事、人物↔作品は双方向に張る（CMSの参照プロパティで自動化） |
| 深さ | トップから3クリック以内に全ページへ到達できること |
| 孤立ページ禁止 | どこからもリンクされていないページを作らない（`scripts/media_validate.py` で検出） |

## 7-6. 計測設計

### 通常のSEO指標

- GSC: 表示回数 / クリック数 / 平均順位（**固有名詞クエリを別途モニタする**）
- GA4: セッション / ページ/セッション / スクロール深度

### AIO指標（重要）

AI検索からの流入は通常のリファラでは捉えにくい。以下を設定する。

| 方法 | 内容 |
|---|---|
| リファラ計測 | GA4で `chatgpt.com` `perplexity.ai` `gemini.google.com` `copilot.microsoft.com` からの参照を**カスタムセグメント化** |
| 引用モニタ | 月1回、主要な問い（ISSUEの `question` 10本）を各AIに投げ、SISIDENが引用されるか手動で確認。**これが最も確実** |
| ブランド言及 | 「SISIDEN」「シシデン」の指名検索数をGSCで追う |

### ダッシュボードに置く5指標

1. 固有名詞クエリの表示回数（人物名・作品名）
2. AI検索リファラのセッション数
3. ページ/セッション（回遊の質）
4. ISSUEページの平均滞在時間
5. 「この物語を映像で見る」のクリック率（記事→YouTubeの送客）

## 7-7. やってはいけないこと

| 禁止 | 理由 |
|---|---|
| 取材していないテーマの解説記事 | 一次情報がない記事はSISIDENの資産にならず、サイト全体の信頼を下げる |
| AI生成による記事量産 | 現場取材という唯一の優位性を自ら消す行為 |
| 「〜とは？」記事の機械的量産 | ISSUEページの価値を薄める。ISSUEは20〜40本で止める |
| タグページの大量index | 薄いページの量産と見なされる |
| 他メディア記事のまとめ | 二次情報メディアになった瞬間に競争優位が消える |
| 記事末尾の定型CTA（「お問い合わせはこちら」） | 編集メディアではなく営業サイトに見える |

## 7-8. robots / インデックス制御

```
index, follow    : 作品 / 記事 / 人物 / 課題 / 地域 / カテゴリ / 各一覧
noindex, follow  : タグページ / 検索結果 / 組織ページ（関連3本未満）
```

- タグページの `noindex` はSTUDIOのページ設定から指定する
- サイトマップからも除外されているか確認（[STEP 3-5](./03-sitemap.md)）
- **`follow` は必ず残す。**回遊グラフを壊さない
