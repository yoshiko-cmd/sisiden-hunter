## D-002 | 2026-09-23 | 技術: WordPressではなく **Astro(静的サイト生成)+ Markdown** を採用 **[仮説]**

プロンプトの指示どおりWordPressを第一候補として比較した。

| 観点 | WordPress | Astro + Markdown(採用) |
|---|---|---|
| 表示速度 / Core Web Vitals | プラグイン次第で悪化しやすい | 静的HTML。JSは無料ツールのページだけ |
| セキュリティ | 本体・プラグインの更新運用が必須 | サーバー側の攻撃面がほぼ無い |
| 費用 | サーバー代が必要 | Cloudflare Pages / Netlify等の無料枠で公開可能 |
| 1000記事規模 | 可能 | 可能(ビルド時間は数十秒〜数分の見込み) |
| 比較表の更新 | 表プラグイン / 手作業 | `src/data/*.json` を1か所直せば全ページへ反映 |
| アフィリエイトリンク管理 | プラグイン | `src/data/offers.json` の台帳 + `/go/<id>` リダイレクト |
| ライター追加 | 管理画面があり強い | **弱い**。Git/Markdownに慣れていない人には難しい |
| バックアップ | 別途必要 | Gitそのものが完全な履歴 |
| この環境で作って検証できるか | サーバーが無く不可 | ビルド・表示確認まで可能 |

- 決め手: 「確認待ちで止まらない」ためには、この環境で最後まで作って確認できることが最重要。
  あわせて、速度とセキュリティで有利。
- 弱点(ライター追加)への対策: 記事は素のMarkdownとfrontmatterで書いてあるので、
  Decap CMS / TinaCMS等のGitベースCMSをあとから載せられる。WordPressへ移る場合も
  Markdown→WXRの変換で移行できる。
- 差し替え条件: 外部ライターが3人以上になり、Gitでの入稿が負担になったとき。

## D-005 | 2026-09-23 | 広告表示の方針

- 広告リンクを含むページは、**記事の冒頭**(タイトル直下)に「この記事には広告(アフィリエイトリンク)を含みます」を表示する。
- さらに**広告リンクそのものの直前**に「PR」ラベルを付ける(冒頭の一文だけに頼らない)。
- 広告リンクは `rel="sponsored nofollow noopener"`。
- 広告主から報酬を受けても、順位・評価は変えない(`/policy/advertising/` に明記)。
- 根拠: 景品表示法の指定告示(ステルスマーケティング規制、2023年10月1日施行)。消費者庁の運用基準・Q&Aでは、
  一般消費者が広告であることを明瞭に判別できる表示が求められている。

## D-006 | 2026-09-23 | 数字・価格・報酬を載せない場合のルール

- サービスの料金・手数料・無料枠・ASP報酬は、**公式ページで確認した日付つき**でしか載せない。
- 未確認の値はサイトに出さず、`[公式で最新確認予定]` と表示する。比較表は「確認日」の列を必ず持つ。
- 今回の調査では go.jp ドメインや多くの公式サイトへ直接アクセスできず、二次情報しか得られなかった
  (BLOCKED B-002)。このため初版の比較表は**比較の観点と、その観点を確かめる方法**に絞り、数字は空欄にしてある。
